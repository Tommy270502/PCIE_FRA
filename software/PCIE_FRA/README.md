# Vendored BSP and FSBL

This directory is **not** hand-written project code. It is the board support
package and first-stage bootloader, originally generated by Vitis from the
exported XSA and since carried in-tree as vendored source.

```
ps7_cortexa9_0/standalone_ps7_cortexa9_0/bsp/
    include/      BSP headers -- what software/FRA_Controller compiles against
    libsrc/       AMD embeddedsw driver and standalone sources (MIT)
    lib/          built archives           <- generated, not tracked
    build/        CMake + Ninja tree       <- generated, not tracked
zynq_fsbl/        first-stage bootloader sources
hw/sdt/           system device tree and ps7_init from the XSA
```

## Why it is checked in

Vitis 2026.1 removed `xsct`, and with it the scripted path that regenerated this
workspace from an XSA. Keeping the sources means the firmware builds from a
clone with nothing but a Vitis toolchain — no IDE session, no workspace import.

The trade is that the *sources* are tracked while everything built from them is
not. Build the archives with:

```bash
make bsp          # or: scripts/build_bsp.sh [--clean]
```

That script exists because the BSP's own CMake project has two traps that each
produce a silently wrong result rather than an error — it resolves its source
directories through `lib/`, so it builds nothing at all when that directory is
absent, and it reads `proc_extra_compiler_flags` before the subdirectory that
sets it, so a single configure pass builds the whole BSP at `-O0`. Both are
handled and asserted there; the comments in the script have the detail.

## Provenance

`bsp.yaml` records which driver versions this BSP was generated from. The paths
in it point at a 2025.1 install on a machine that no longer exists — that is
historical record, not configuration, and nothing reads them. It is kept because
the version list is the only thing that identifies what these sources are.

## Changing anything here

Don't, as a rule. Local edits to vendored sources are invisible to anyone
reading the project and are lost the moment the workspace is regenerated. If a
driver genuinely needs a change, note it in [CHANGELOG.md](../../CHANGELOG.md)
so the next person regenerating the BSP knows to reapply it.
